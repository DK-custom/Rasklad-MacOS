# Всплывающие подсказки у курсора ввода: перенос с macOS на Windows

Задание для реализации (Codex). Описывает, как подсказки сделаны в Rasklad для macOS (`Sources/Hint.swift`),
и как то же самое собрать на Windows. Windows-часть не проверялась на практике: API указаны по документации,
каждый пункт «проверить» нужно подтвердить на живой системе.

## 1. Что должно получиться

Маленькое окно рядом с редактируемым словом, которое **не забирает фокус** — пользователь продолжает печатать.

| Событие | Текст | Скрытие |
|---|---|---|
| Автозамена раскладки или опечатки | `ghbdtn → привет   правый Alt — отменить` | через 2 с |
| Отмена замены | `↩ ghbdtn   добавлено в исключения` | через 1,5 с |
| Определение слова (Shift + правый Alt) | текст словарной статьи, до 320 px высоты, с прокруткой | по любой клавише или клику **вне** окна |

Вид: шрифт мелкий и тонкий (на macOS — системный 11 pt Light, определение 12 pt), отступы 8×4 px,
скруглённые углы 8 px, тень, фон по системной теме (светлая/тёмная). Ширина: уведомление до 360 px, определение до 420 px;
короткий текст — окно по ширине текста.

## 2. Как устроено на macOS (для понимания)

1. **Позиция курсора** через Accessibility: фокусный элемент → выделенный диапазон
   (`kAXSelectedTextRangeAttribute`) → экранный прямоугольник диапазона (`kAXBoundsForRangeParameterizedAttribute`).
   Если выделения нет — берётся символ перед курсором (диапазон `location-1, length 1`). Таймаут запроса 0,2 с.
2. **Нет позиции** (приложение не отдаёт: Electron, терминалы) → подсказка у указателя мыши.
3. **Окно**: панель без рамки, `nonactivatingPanel`, уровень поверх всего, на всех рабочих столах.
4. **Показ** через 120 мс после синтетического перенабора слова — чтобы поле успело обновиться и курсор встал на место.
5. **Закрытие** «липкой» подсказки делает уже существующий перехват клавиатуры/мыши: любое нажатие — закрыть,
   клик — закрыть, если он не внутри подсказки.
6. **Диагностика**: в лог пишется, откуда взялась позиция (`у курсора` / `у мыши`) и в каком приложении — без самих слов.

## 3. Реализация на Windows

### 3.1 Позиция курсора: цепочка источников

Пробовать по порядку, первый успешный — результат. Все координаты — экранные, в физических пикселях.

1. **UI Automation, TextPattern** (WPF, UWP/WinUI, Office, Chrome/Edge, Firefox, Windows Terminal, большинство современных приложений):
   - `IUIAutomation::GetFocusedElement`
   - `TextPattern2::GetCaretRange` (если есть) или `TextPattern::GetSelection` → первый диапазон
   - если диапазон пустой — `ExpandToEnclosingUnit(TextUnit_Character)` или сдвиг на символ назад, как на macOS
   - `ITextRangeProvider::GetBoundingRectangles` → первый прямоугольник
2. **MSAA caret**: `AccessibleObjectFromWindow(hwndFocus, OBJID_CARET, IID_IAccessible)` → `accLocation`.
   Часто работает в Chromium/Electron и старых приложениях.
3. **Win32 caret**: `GetGUIThreadInfo(threadOfForegroundWindow)` → `rcCaret` + `hwndCaret` → `ClientToScreen`.
   Работает для классических Win32-полей (Notepad старых версий, диалоги).
4. **Fallback**: `GetCursorPos` (указатель мыши), прямоугольник 1×16.

Проверять результат: прямоугольник ненулевой высоты, не `(0,0)`, лежит на каком-нибудь мониторе
(`MonitorFromRect(..., MONITOR_DEFAULTTONULL)` не NULL). Иначе — следующий источник.

### 3.2 Окно подсказки

- `CreateWindowEx` со стилями `WS_EX_TOOLWINDOW | WS_EX_TOPMOST | WS_EX_NOACTIVATE`, стиль `WS_POPUP`.
  Для уведомлений дополнительно `WS_EX_TRANSPARENT | WS_EX_LAYERED` — клики проходят насквозь.
  Для определения `WS_EX_TRANSPARENT` не ставить (нужна прокрутка колесом), а на `WM_MOUSEACTIVATE` возвращать `MA_NOACTIVATE`.
- Показ только `ShowWindow(SW_SHOWNOACTIVATE)` и `SetWindowPos(HWND_TOPMOST, ..., SWP_NOACTIVATE | SWP_SHOWWINDOW)`.
  Никогда `SetForegroundWindow` — иначе фокус уйдёт из поля ввода.
- Скругление и тень на Windows 11: `DwmSetWindowAttribute(DWMWA_WINDOW_CORNER_PREFERENCE, DWMWCP_ROUNDSMALL)`.
  На Windows 10 — регион `CreateRoundRectRgn` или просто прямые углы.
- Текст: DirectWrite (или GDI), шрифт Segoe UI Semilight/Light, ~9 pt; размер окна считать по измерению текста
  с учётом DPI монитора, где показывается подсказка (`GetDpiForWindow` / `GetDpiForMonitor`).
- Тема: `HKCU\Software\Microsoft\Windows\CurrentVersion\Themes\Personalize\AppsUseLightTheme` (0 — тёмная).
- Процесс: Per-Monitor DPI Aware v2 (манифест или `SetProcessDpiAwarenessContext`), иначе координаты UIA и окна
  разъедутся на мониторах с разным масштабом.

### 3.3 Расположение (перенести один в один, с тестом)

На Windows ось Y направлена **вниз** (на macOS — вверх), поэтому формула зеркальная. Работать в границах
рабочей области монитора (`GetMonitorInfo(MonitorFromRect(anchor)).rcWork`).

```
gap = 6, margin = 4
x = clamp(anchor.left, work.left + margin, work.right - width - margin)
y = anchor.top - gap - height                 // над словом
if y < work.top + margin: y = anchor.bottom + gap   // у верхнего края — под словом
y = min(y, work.bottom - height - margin)
```

Тест-кейсы (work = 0,0–1000×800; окно 200×30; anchor 10×18):

| anchor.left, anchor.top | Ожидаемо (x, y) | Случай |
|---|---|---|
| 100, 300 | 100, 264 | над словом: 300−6−30 |
| 100, 10 | 100, 34 | у верхнего края — под словом: 10+18+6 |
| 950, 300 | 796, 264 | у правого края: 1000−200−4 |
| −50, 300 | 4, 264 | за левым краем |

### 3.4 Время и закрытие

- Показ уведомления — через ~120 мс после отправки синтетического перенабора (`SendInput`), позиция запрашивается
  в этот момент, а не раньше.
- Новая подсказка заменяет текущую и сбрасывает её таймер.
- «Липкая» подсказка (определение) закрывается из уже существующих хуков `WH_KEYBOARD_LL` / `WH_MOUSE_LL`:
  любая клавиша пользователя — закрыть; клик — закрыть, если точка не внутри окна подсказки.
  Свои синтетические события отличать по метке в `dwExtraInfo` (аналог `eventSourceUserData` на macOS) и не учитывать.

## 4. Ловушки

- **Хуки нельзя задерживать.** Low-level hook должен вернуть управление быстро (порог `LowLevelHooksTimeout`,
  на Windows 10+ хук при превышении может быть тихо снят). Запросы UIA/MSAA и показ окна — не в колбэке хука,
  а через `PostMessage` в свой поток/окно.
- **Таймаут на UIA.** Зависшее приложение не должно вешать утилиту: запрос позиции в отдельном потоке
  с лимитом ~200 мс, по истечении — fallback к мыши.
- **COM-потоки.** UIA-клиент инициализировать в своём потоке (`CoInitializeEx`), события UIA не подписывать — только
  разовые запросы.
- **Повышенные права (UIPI).** Из обычного процесса нельзя читать UIA у окон, запущенных от администратора,
  и `SendInput` в них не дойдёт. Для таких окон — fallback к мыши (и автозамена там тоже не сработает).
- **Chromium/Electron** включает дерево доступности по запросу; первый запрос может вернуть пустоту — это нормально,
  fallback к MSAA caret или мыши.
- **Полноэкранные приложения и безопасный рабочий стол** (UAC, экран входа): подсказку не показывать.
- **Множество мониторов с разным DPI** — проверять обязательно (см. 3.2).

## 5. Диагностика

Писать в лог при каждом показе: источник позиции (`uia` / `msaa` / `win32caret` / `mouse`) и имя процесса
переднего окна. **Не писать сами слова** — это по сути запись набора с клавиатуры.

## 6. Чек-лист проверки

1. Блокнот (Windows 11), Word, Chrome, Edge, VS Code, Telegram/Slack (Electron), Windows Terminal, классический диалог Win32.
2. Для каждого: источник позиции по логу, подсказка над словом, фокус остаётся в поле (печать продолжается без клика).
3. Слово у верхнего края экрана → подсказка под словом; у правого края → прижата внутрь.
4. Два монитора с разным масштабом (100% и 150%): подсказка у слова на обоих.
5. Определение: прокрутка колесом работает, клик внутри не закрывает, Esc или клик мимо закрывает.
6. Окно приложения, запущенного от администратора: утилита не падает, подсказка у мыши.
