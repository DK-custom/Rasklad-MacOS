# Работа со встроенными словарями: перенос с macOS на Windows

Задание для реализации (Codex). Описывает, как Rasklad на macOS решает «это слово или нет», исправляет опечатки
и показывает определения (`Sources/Detector.swift`, `Sources/Settings.swift`, `Tests/main.swift`),
и чем это заменить на Windows. Windows-часть не проверялась на практике: API указаны по документации,
пункты «проверить» нужно подтвердить на живой системе. Готовые тест-кейсы — раздел 7.

## 1. Где словари участвуют

| Задача | macOS | Windows |
|---|---|---|
| Слово существует в языке? (автопереключение) | `NSSpellChecker.checkSpelling` | Spell Checking API: `ISpellChecker::Check` |
| Исправление опечатки | `NSSpellChecker.correction` | `ISpellChecker::Suggest` (+ автозамена `CORRECTIVE_ACTION_REPLACE`) |
| Пользовательский словарь («запомнить слово») | `~/Library/Spelling/LocalDictionary`, `learnWord` | `ISpellChecker::Add`, файл `default.dic` |
| Определение слова | `DCSCopyTextDefinition` (словари приложения «Словарь») | системного аналога нет — см. раздел 5 |
| Таблица соответствия клавиш RU/EN | `UCKeyTranslate` по раскладкам | `ToUnicodeEx` по `HKL` раскладок |

## 2. Проверка «слово существует»

**macOS.** `checkSpelling(of:startingAt:language:...)` с языком `ru` или `en`; слово верное, если `location == NSNotFound`.
Знаки препинания проверка пропускает сама (`Ghbdtn^` → `Привет,` проверяется как слово).

**Windows.** Spell Checking API (Windows 8+, `spellcheck.h`, COM):

1. `CoCreateInstance(CLSID_SpellCheckerFactory)` → `ISpellCheckerFactory`.
2. `IsSupported(L"ru-RU")`, `IsSupported(L"en-US")` — если `FALSE`, нужен языковой пакет
   (Параметры → Время и язык → Язык → добавить русский; компонент проверки орфографии ставится вместе с ним).
   Сообщить пользователю, не падать.
3. `CreateSpellChecker(lang)` → `ISpellChecker`, держать по одному на язык.
4. `Check(word)` → `IEnumSpellingError`; ошибок нет — слово верное.

Слово проверять **без** окружающей пунктуации (ядро — от первой до последней буквы), чтобы не зависеть от того,
как конкретный движок трактует знаки. Проверить, как Windows-движок ведёт себя с апострофом и дефисом.

### Обязательные поправки к «голой» проверке (выяснено на macOS, проверить на Windows)

1. **Слова целиком заглавными** macOS считает аббревиатурами и всегда принимает (даже `XYZQW`).
   Поэтому если в слове ≥2 букв и все заглавные — проверять его **строчными**. На Windows проверить тестом
   из раздела 7; у `ISpellChecker` есть опции (`GetOptionValue`, список — `get_OptionIds`), возможно, там же
   игнорирование заглавных — но надёжнее та же нормализация.
2. **Слова до 3 букв** движок проверки принимает почти любые: одиночные буквы, сокращения, редкие формы
   (`z`, `шт`, `ру`, `иге`, `tot`). Для них словарь **не используется вообще** — решение по спискам частых
   коротких слов (раздел 3).

## 3. Решение о переключении раскладки

Буфер слова хранит **нажатые клавиши** (скан-код + Shift + Caps Lock), а не символы. Из одного буфера строятся
два прочтения: в текущей раскладке (`typed`) и в другой (`other`). Caps Lock хранится отдельно для каждого
нажатия и действует как Shift **только на буквах конкретной раскладки** (клавиша `'` в EN — знак, в RU — буква «э»).

Правило (по пробелу; Tab и Enter не запускают проверку):

```
letters = max(букв в other, букв в typed)
если 1 ≤ letters ≤ 3:
    // сравнивать одинаковые позиции: где буква хотя бы в одной раскладке
    // (на месте буквы может стоять знак: «ё» на клавише \, «ю» на точке)
    o, t = other и typed по этим позициям, строчными
    переключить, если o ∈ частые[целевой язык] и t ∉ частые[текущий язык]
иначе:
    переключить, если typed — не слово в текущем языке, а other — слово в целевом
```

Списки частых коротких слов — `commonShort` в `Sources/Detector.swift` (~90 русских, ~100 английских).
Перенести как данные. Проверено: ни одно слово одного списка не превращается в слово другого при смене раскладки.
Тест гоняет оба списка целиком в обе стороны (раздел 7).

После правила — **исключения** (раздел 6): если `typed` или `other` в списке, не трогать.

## 4. Исправление опечаток

Только если раскладка верная (правило раздела 3 ничего не нашло). Здесь — словарная часть;
полная механика (буфер, замена в поле, отмена, ловушки) — в `TYPOS_WINDOWS.md`.

1. Ядро слова — от первой до последней буквы; знаки по краям сохраняются (`Првиет!` → `Привет!`).
2. Не трогать: ядро короче 4 букв; ядро содержит что-то кроме букв, `-`, `'`; все буквы заглавные (аббревиатура).
3. Ядро — верное слово → ничего не делать.
4. Вариант исправления: на macOS `correction(forWordRange:...)` (один лучший вариант).
   На Windows: если `Check` вернул ошибку с `CORRECTIVE_ACTION_REPLACE` — взять `Replacement` (встроенная автозамена);
   иначе `Suggest(word)` → первый вариант.
5. Принять вариант, только если в нём нет пробела и расстояние небольшое:
   **≤1 правка для слов 4–6 букв, ≤2 для слов от 7 букв.** Расстояние — Левенштейн с перестановкой соседних
   символов за одну правку (optimal string alignment, `editDistance` в `Detector.swift`), сравнивать строчными.
6. Регистр: на macOS движок сам возвращает вариант в регистре исходного (`Првиет` → `Привет`).
   На Windows проверить; при необходимости переносить заглавную первую букву вручную.

Известная особенность: движок может выбрать не тот вариант (`helo` → `help`, а не `hello`). Это лечится отменой
(правый Alt сразу после замены возвращает набранное и добавляет слово в исключения).

## 5. Определение слова

**macOS.** `DCSCopyTextDefinition(nil, word, range)` — плоский текст статьи из словарей приложения «Словарь»
(для русских слов — толковый словарь, для английских — англо-русский). Нет статьи → `nil` → подсказка
«слова нет в словарях».

**Windows.** Системного API словарных статей нет. Варианты, по возрастанию сложности:

1. **Без определений** — честно отключить функцию на Windows.
2. **Локальный словарь, поставляемый с утилитой**: например, WordNet для английского (свободная лицензия);
   для русского — открытые словари, лицензию проверить перед включением в поставку. Хранить в SQLite
   (`слово → статья`), искать по нормальной форме слова (нижний регистр; для русского желательно лемматизация,
   иначе «работает» не найдёт «работать»).
3. **Онлайн-словарь** — только по явному согласию пользователя: выделенное слово уходит в сеть.

Интерфейс оставить тем же: `define(word) → текст | null`, показ — «липкая» подсказка у курсора (см. `HINTS_WINDOWS.md`).

## 6. Пользовательские словари и исключения

Два разных механизма, не смешивать:

- **Пользовательский словарь движка** — «это слово существует». macOS: пункт «Запомнить написание» в контекстном
  меню любого приложения пишет в `~/Library/Spelling/LocalDictionary`; проверка сразу его учитывает
  (проверено: `learnWord` → слово верное, `unlearnWord` → снова нет). На macOS словарь общий для всех языков.
  Windows: `ISpellChecker::Add(word)` — пишет в пользовательский словарь языка
  (`%AppData%\Microsoft\Spelling\<язык>\default.dic`, проверить путь); `Ignore(word)` — только на время сессии.
- **Исключения утилиты** — «это слово не трогать». Текстовый файл, по слову в строке, `#` — комментарий,
  слово в любой раскладке. Нормализация: нижний регистр, обрезать пунктуацию, символы и пробелы по краям.
  Совпадение по `typed` **или** `other`. Файл перечитывать при каждой проверке (маленький) — правки сразу действуют.
  Отмена автозамены дописывает набранное слово в этот файл.

Плюс список приложений-исключений (по имени процесса на Windows вместо bundle id), где автозамена выключена,
а ручные команды (правый Alt) работают.

## 7. Тест-кейсы (перенести в самопроверку, без фреймворков)

Раскладка неверная (набрано → результат), Mac «Russian»; **на Windows пунктуация другая** — запятая в русской
раскладке на клавише `/` с Shift? (проверить по `ToUnicodeEx`), поэтому кейсы с пунктуацией пересчитать
из таблицы, а не копировать:

| Набрано | В раскладке | Ожидаемо |
|---|---|---|
| `ghbdtn` | EN | `привет` |
| `yt` | EN | `не` |
| `руддщ` | RU | `hello` |
| `рщц` | RU | `how` |
| `e` | EN | `у` (частое однобуквенное) |
| `hello` | EN | не трогать |
| `привет` | RU | не трогать |
| `i` | EN | не трогать (само частое) |
| `qwzx`, `qz` | EN | не трогать (мусор в обеих) |
| `123` | EN | не трогать |
| `RFR`, `HF,JNFTN` с Caps Lock | EN | `КАК`, `РАБОТАЕТ` |
| `'NJ` с Caps Lock | EN | `ЭТО` (на этой клавише в RU буква) |
| `HELLO` с Caps Lock | EN | не трогать |
| все слова `commonShort` | неверная | исправлены; в верной — не тронуты |

Опечатки:

| Набрано | Ожидаемо |
|---|---|
| `првиет`, `Првиет!` | `привет`, `Привет!` |
| `нормлаьно` | `нормально` (перестановка = 1 правка) |
| `becuase` | `because` |
| `teh` | не трогать (короче 4) |
| `HELO` | не трогать (аббревиатура) |
| `спасибо` | не трогать (верное) |
| `asdfgh` | не трогать (нет варианта) |

Расстояние: `нормлаьно/нормально` = 1, `работет/работает` = 1, `helo/help` = 1, `kitten/sitting` = 3.

Проверки движка (выполнить первыми на Windows — от них зависят поправки раздела 2):
`XYZQW` в en-US верное? `RFR` верное? `z`, `шт`, `иге` верные? Если да — нормализация и списки обязательны.

## 8. Таблица клавиш RU/EN (от неё зависят все прочтения слова)

Не хардкодить: раскладки различаются (на Mac «Russian» и «Russian – PC» разная пунктуация, на Windows — своя).
Windows: `GetKeyboardLayoutList` → найти `HKL` с языком 0x0419 (русский) и 0x0409 (английский);
для каждой клавиши основного блока и состояний Shift вызвать `ToUnicodeEx(vk, scan, keyState, buf, ..., flags, hkl)`.
Флаг «не менять состояние мёртвых клавиш» (`flags` бит 2, Windows 10 1607+) — проверить, иначе вызов портит
ввод с мёртвыми клавишами. Строить отображение «клавиша+Shift → символ» для каждой раскладки и из него — обе
стороны конвертации. Буфер слова хранить в виде клавиш, символы — только по запросу.
