# Исправление опечаток при наборе: перенос с macOS на Windows

Задание для реализации (Codex). Полная механика автоисправления мелких опечаток в Rasklad для macOS
(`Sources/KeyTap.swift` — перехват и замена, `Sources/Detector.swift` — `typoFix`, `editDistance`)
и её перенос на Windows. Проверка слов и варианты исправлений — в `DICTIONARIES_WINDOWS.md` (разделы 2 и 4),
подсказка над словом — в `HINTS_WINDOWS.md`. Windows-часть не проверялась на практике.

## 1. Поведение

Пользователь набирает слово с мелкой ошибкой и пробел — слово заменяется исправленным, над ним на 2 с
появляется `првиет → привет   правый Alt — отменить`. Правый Alt сразу после этого возвращает набранное
и навсегда добавляет слово в исключения. Функция включается/выключается в меню независимо от автопереключения
раскладки; выбор сохраняется. В приложениях из списка исключений не работает.

Примеры: `првиет` → `привет`, `Првиет!` → `Привет!`, `нормлаьно` → `нормально`, `работет` → `работает`,
`becuase` → `because`. Не трогаются: `teh` (короче 4), `HELO` (аббревиатура), `asdfgh` и `kubernetes`
(нет варианта), верные слова.

## 2. Конвейер

```
клавиша → буфер слова → пробел → [раскладка неверна?] → да: замена раскладки
                                                      → нет: [опечатка?] → да: замена слова
                                                                        → нет: ничего
```

### 2.1 Буфер слова (общий с автопереключением)

Low-level хук клавиатуры (`WH_KEYBOARD_LL`). Буфер — список нажатий (скан-код/VK + Shift + Caps Lock), не символы.

| Событие | Действие с буфером |
|---|---|
| буквенно-цифровая клавиша основного блока | добавить нажатие |
| Backspace | убрать последнее |
| Пробел | **проверить слово**, затем очистить |
| Enter, Tab | очистить без проверки |
| стрелки, Esc, F-клавиши, Home/End и т. п. | очистить |
| любая клавиша с Ctrl / Alt / Win | очистить |
| клик мыши | очистить (курсор мог переместиться) |
| свои синтетические события (метка в `dwExtraInfo`, флаг `LLKHF_INJECTED`) | игнорировать |

### 2.2 Порядок проверок по пробелу

1. Нет буфера, неизвестна текущая раскладка или приложение в исключениях — выход.
2. `typed` = буфер, прочитанный в текущей раскладке.
3. Автопереключение включено и правило раскладки сработало (см. `DICTIONARIES_WINDOWS.md`, раздел 3) →
   замена раскладки (если не исключение). **Опечатки в этом случае не проверяются.**
4. Иначе, если исправление опечаток включено и `typed` не в исключениях → `typoFix(typed, язык текущей раскладки)`.
5. Есть результат → замена (раздел 3).

## 3. Правило `typoFix`

```
core = typed от первой до последней буквы        // знаки по краям — prefix / suffix
нет букв → нет исправления
len(core) < 4 → нет
core содержит что-то кроме букв, '-', '\'' → нет
все буквы core заглавные → нет                   // аббревиатура
core — верное слово (с нормализацией CAPS из DICTIONARIES_WINDOWS.md) → нет
fixed = лучший вариант движка для core           // нет варианта → нет
fixed == core или содержит пробел → нет
editDistance(lower(core), lower(fixed)) > (len(core) >= 7 ? 2 : 1) → нет
результат = prefix + fixed + suffix
```

Лучший вариант на Windows: ошибка `Check` с `CORRECTIVE_ACTION_REPLACE` → её `Replacement`; иначе первый из `Suggest`.
Регистр: на macOS вариант уже приходит в регистре исходного (`Првиет` → `Привет`); на Windows проверить и при
необходимости перенести заглавную первую букву.

### 3.1 Расстояние

Левенштейн с перестановкой соседних символов за одну правку (optimal string alignment):

```
d[i][0] = i, d[0][j] = j
d[i][j] = min(d[i-1][j] + 1, d[i][j-1] + 1, d[i-1][j-1] + (a[i-1] != b[j-1]))
если i>1, j>1, a[i-1] == b[j-2], a[i-2] == b[j-1]:
    d[i][j] = min(d[i][j], d[i-2][j-2] + 1)
```

Сравнивать по символам (не по UTF-16 единицам — для кириллицы совпадает, но для эмодзи и составных символов нет).

## 4. Замена в поле ввода

Слово уже набрано и **пробел уже доставлен** в приложение (хук только слушает). Поэтому:

1. Стереть `len(буфер) + 1` символов: столько раз Backspace (`SendInput`, `VK_BACK`).
2. Набрать `результат + " "` как Unicode: `SendInput` с `KEYEVENTF_UNICODE`, по одному UTF-16 коду на событие
   (keydown + keyup), без привязки к раскладке.
3. Все свои события пометить в `dwExtraInfo` — хук их пропускает, буфер и «окно отмены» они не сбивают.
4. Модификаторы в синтетических событиях не должны унаследоваться от физически зажатых (на macOS флаги
   выставляются явно пустыми; на Windows проверить, что зажатый Shift не превращает Backspace во что-то иное).
5. Отправлять не из колбэка хука, а через `PostMessage` в свой поток: хук должен вернуться быстро.
6. Раскладку при исправлении опечатки не менять (на macOS тот же `retype`, но целевая раскладка = текущая).

Если раскладка всё-таки переключается (замена раскладки), сохранить Caps Lock: на macOS программное
переключение раскладки его сбрасывает. На Windows проверить, сбрасывает ли `ActivateKeyboardLayout`/
`WM_INPUTLANGCHANGEREQUEST`; если да — вернуть состояние.

## 5. Отмена (правый Alt)

- После замены запомнить `lastFix = (typed, язык, результат)`.
- `lastFix` живёт до **следующего действия пользователя**: любая клавиша (кроме модификаторов) или клик — сбросить.
- Одиночное нажатие правого Alt (нажали и отпустили без других клавиш; Ctrl/Win/левый Alt не зажаты):
  если `lastFix` есть — стереть `len(результат) + 1`, набрать `typed + " "`, вернуть раскладку,
  дописать `typed` в файл исключений, показать `↩ typed   добавлено в исключения` на 1,5 с.
- Правый Alt на Windows в русской/европейских раскладках может работать как AltGr (= Ctrl+Alt): хук увидит
  `VK_RMENU` и синтетический `VK_LCONTROL`. Это нужно учесть в распознавании «одиночного» нажатия — проверить.

## 6. Ловушки

- **Поля паролей.** На macOS система сама не отдаёт нажатия в полях паролей (Secure Input). На Windows
  low-level хук видит **всё**, включая пароли. Перед проверкой слова спросить UIA фокусный элемент:
  `UIA_IsPasswordPropertyId == TRUE` → не исправлять и не держать буфер. Если UIA недоступен — лучше не исправлять.
- **Приложения со своей автозаменой** (Word, Outlook): двойное исправление. Слово, уже исправленное приложением,
  обычно станет верным и утилита его не тронет, но порядок событий может отличаться — проверить в Word;
  при конфликте — добавить Office в исключения по умолчанию.
- **IME и составной ввод** (китайский, японский, а также мёртвые клавиши): буфер по нажатиям не совпадает с текстом.
  При активном IME не исправлять.
- **Повышенные права (UIPI):** `SendInput` не доходит до окон администратора — замену там не делать.
- **Спорные варианты** движка (`helo` → `help`) — норма; лечится отменой, которая заносит слово в исключения.
- **Журнал:** в лог только факт и приложение, **не слова** — иначе утилита становится кейлоггером.
  Запись слов — только отладочный флаг, выключенный по умолчанию.

## 7. Тесты (без фреймворков, assert-самопроверка)

С подставным вариантом (проверка правила без движка):

| typed | вариант | ожидаемо |
|---|---|---|
| `helo,` | `help` | `help,` |
| `teh` | `the` | нет (короче 4) |
| `wrdo` | `world` | нет (расстояние 2 у короткого) |
| `becuase` | `because` | `because` |
| `HELO` | `HELP` | нет (аббревиатура) |
| `abcd` | нет варианта | нет |

С живым движком: `првиет` → `привет`, `Првиет!` → `Привет!`, `нормлаьно` → `нормально`, `becuase` → `because`,
`спасибо` → нет, `asdfgh` → нет.

Расстояние: `нормлаьно/нормально` = 1, `работет/работает` = 1, `helo/help` = 1, `kitten/sitting` = 3.

Вживую: Блокнот, браузер, Word (двойная автозамена), поле пароля (не трогается), окно администратора (не падает),
отмена правым Alt сразу после замены и после ещё одной клавиши (не срабатывает).
